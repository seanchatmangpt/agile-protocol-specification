# Filename Examples

This document provides clear examples of how to apply the Agile Protocol Specification (APS) naming conventions to files. These examples illustrate the standardized format and demonstrate how metadata is embedded directly into filenames.

## Standard Filename Format

The standard format for filenames within the APS is:

`<Component>_<Type>_<State>_<Role>_<Date>_<Version>_<Author>.<Extension>`

### Example 1: Product Vision Document

**Filename:** `ProductDevelopment_Vision_Draft_APM_2024-03-15_v0.1.0_JS.md`

- **Component:** `ProductDevelopment` (Indicates the document relates to product development)
- **Type:** `Vision` (Specifies the document type as a product vision statement)
- **State:** `Draft` (Shows the document is in the draft stage)
- **Role:** `APM` (Identifies the role as Adversarial Product Management)
- **Date:** `2024-03-15` (Indicates the creation or last modification date)
- **Version:** `v0.1.0` (Reflects the document version)
- **Author:** `JS` (Represents the initials of the author, John Smith)
- **Extension:** `.md` (Denotes the file format as Markdown)

### Example 2: Customer Journey Map

**Filename:** `CustomerSupport_JourneyMap_InReview_UX_2024-03-22_v1.2.0_AB.mermaid`

- **Component:** `CustomerSupport` (Indicates the document relates to customer support)
- **Type:** `JourneyMap` (Specifies the document type as a customer journey map)
- **State:** `InReview` (Shows the document is currently under review)
- **Role:** `UX` (Identifies the role as User Experience)
- **Date:** `2024-03-22` (Indicates the creation or last modification date)
- **Version:** `v1.2.0` (Reflects the document version)
- **Author:** `AB` (Represents the initials of the author, Alice Brown)
- **Extension:** `.mermaid` (Denotes the file format as a MermaidJS diagram)

### Example 3: Sprint Backlog

**Filename:** `Engineering_SprintBacklog_Accepted_Dev_2024-04-05_v2.0.0_PM.xlsx`

- **Component:** `Engineering` (Indicates the document relates to the engineering team)
- **Type:** `SprintBacklog` (Specifies the document type as a sprint backlog)
- **State:** `Accepted` (Shows the document has been accepted and finalized)
- **Role:** `Dev` (Identifies the role as Development)
- **Date:** `2024-04-05` (Indicates the creation or last modification date)
- **Version:** `v2.0.0` (Reflects the document version)
- **Author:** `PM` (Represents the initials of the author, Project Manager)
- **Extension:** `.xlsx` (Denotes the file format as Excel spreadsheet)

## Benefits of Using Examples

- **Clarity and Understanding:** Examples provide a clear and practical illustration of how to apply the naming conventions.
- **Consistency and Standardization:** By following these examples, teams can ensure consistency in file naming across the APS.
- **Reduced Errors:** Clear examples minimize the risk of errors or inconsistencies in file naming.
- **Improved Communication:** Standardized filenames enhance communication and collaboration among team members and AI tools.

By adhering to these filename examples, the APS ensures that all documents are easily identifiable, well-organized, and contribute to a streamlined and efficient agile workflow.
