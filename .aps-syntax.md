# APS Syntax — v26.8.24 Candidate

APS syntax describes a bounded transition from observed reality to a qualified consequence.

## Core symbols

```text
O   observed knowledge
O*  admitted bounded knowledge
C   contract
M   candidate manufacturing space
mu  manufacturing function
A   manufactured artifact/consequence
E   evidence
S   standing
```

## Core transition

```text
O -> admit -> O* -> C -> M -> select/construct -> A -> verify(E) -> S
```

Consequential execution inserts an explicit authority boundary:

```text
proposal -> admission/refusal -> authorized executor -> consequence -> evidence -> standing
```

## Manufacturing equation

```text
A = mu(O*)
```

This equation does not itself grant `ALIVE` standing.

## Reconstitution

```text
S_t -> observe -> O*_t -> {mu_i} -> candidate S_(t+1) -> qualify -> sunset?(S_t)
```

## Chatman's Law

```text
past_cost !-> preservation_privilege
```

and, as remanufacture cost falls:

```text
preservation_privilege(A) -> required irrecoverable information still trapped in A
```

## Consequence classes

```text
SELECT     choose/rank; no external consequence
CONSTRUCT  manufacture artifacts/plans; no ambient execution authority
DO         consequential external actuation; explicit authority required
```

## Standing

```text
ALIVE
PARTIAL_ALIVE
BLOCKED
BUILD_BROKEN
UNKNOWN
UNSUPPORTED
REFUSED(reason)
```

`UNKNOWN` is never promoted to success by prose.
