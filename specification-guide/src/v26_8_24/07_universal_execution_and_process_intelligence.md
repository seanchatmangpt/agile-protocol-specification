# Universal Execution and Full Process Intelligence

The enterprise phase change is incomplete if only code generation changes. APS requires state, action, evidence, and process intelligence to converge on the same admitted semantics.

## Universal execution surface

`clap-noun-verb-any` and `clap-noun-verb-deploy` illustrate the target law:

```text
arbitrary executable
  + admitted command schema
  -> validated invocation
  -> admission policy
  -> explicit executor
  -> execution record
  -> replay verification
```

A legacy or foreign executable does not need to become architectural authority to participate. Its observable command contract can be acquired, admitted, wrapped, governed, and measured.

One command graph can project multiple interaction/deployment surfaces such as CLI, MCP, HTTP, Kubernetes, OCI/container, and future transport adapters. Those surfaces are projections of capability rather than separately authored enterprise applications.

## OCEL parity

A heterogeneous execution fleet becomes far more valuable when native, generated, and wrapped capabilities emit structurally comparable event evidence.

The target is:

```text
execution
  -> semantic identity
  -> OCEL / provenance / receipt
  -> comparable enterprise event corpus
```

This removes the assumption that each technology deserves a bespoke observability model.

## Process intelligence for the whole enterprise

Process intelligence is not limited to software delivery. Any consequential enterprise process can emit evidence against semantic subjects, including:

- order-to-cash;
- procure-to-pay;
- hire-to-retire;
- credit approval;
- claims;
- compliance;
- treasury;
- supply chain;
- incidents;
- customer service;
- software manufacture;
- SaaS actions;
- AI/agent actions.

A minimal event law is:

```text
semantic subject
+ activity
+ authority
+ time
+ input/output identity
+ observed consequence
+ evidence coordinate
```

## Closed-loop enterprise design

The desired loop is:

```text
semantic authority
  -> contract
  -> DfCM candidate manufacture
  -> bounded execution
  -> OCEL / provenance / receipts
  -> process mining / conformance / performance / risk
  -> candidate knowledge change
  -> admission
  -> remanufacture
```

This turns process intelligence from a retrospective dashboard into part of the design feedback system.

## Evidence is a product of execution

Traditional enterprises often reconstruct evidence later through interviews, screenshots, tickets, audit sampling, and manually reconciled reports.

APS instead requires consequential execution to manufacture evidence as a first-class result.

```text
consequence without evidence -> insufficient standing
```

The model/session that proposed an action is not the evidence store. Evidence must survive the agent, process, implementation, and organizational turnover that produced it.

## Process conformance is not process fitness

A dangerous enterprise can conform perfectly to a bad process. Therefore APS separates:

```text
conformance: did execution follow admitted process law?
fitness:     is that process achieving admitted objectives within risk and constraint?
```

Full process intelligence must support both. Adversarial requirements should include cases where the approved process itself is the failure mode.

## The enterprise as a measurable execution graph

When state and action are semantically addressable and consequential operations emit comparable evidence, the enterprise can be analyzed as a continuously evolving execution graph rather than a portfolio of opaque applications.
