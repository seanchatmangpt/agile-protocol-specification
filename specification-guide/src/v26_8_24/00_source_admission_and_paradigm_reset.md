# Source Admission and Paradigm Reset

**Edition:** v26.8.24 candidate  
**Base evidence coordinate:** `main@ab04337b2db63c66fa23c217bf76622fc9c73b6d`

APS v26.8.24 is a first-principles reconstitution of the specification. The predecessor corpus is evidence, not design authority.

## Governing premise

Everything already produced is a sunk cost. Historical effort, code volume, installed base, organizational prestige, language choice, repository topology, documentation, tests, templates, and even APS itself receive no continuation privilege merely because they exist.

The admissible question is prospective:

> Given current knowledge, constraints, objectives, evidence, and available manufacturing capability, what should exist next?

Past artifacts may contain valuable knowledge. They therefore receive **observation rights**, not **preservation rights**.

## Zero continuation privilege; zero uninformed elimination

APS adopts two coupled laws:

1. **Zero continuation privilege.** An incumbent implementation does not automatically propagate into its successor.
2. **Zero uninformed elimination.** An incumbent is not discarded until the knowledge necessary to preserve required truth has been recovered or its absence explicitly admitted.

This yields the reconstitution form:

```text
predecessor
  -> observe
  -> recover contracts, invariants, semantics, evidence, failures
  -> admit bounded knowledge
  -> manufacture successor candidates
  -> independently qualify
  -> assign standing
  -> admit or refuse predecessor sunset
```

## APS is not an agile documentation method

APS is no longer defined primarily as a document lifecycle framework. It is a protocol specification for **knowledge-work remanufacture under explicit standing**.

Its object is the transition:

```text
intent / observations
        -> admitted knowledge
        -> contract
        -> manufacturing search space
        -> lawful manufacture
        -> bounded actuation
        -> process evidence
        -> independent qualification
        -> standing
        -> reusable knowledge
```

Markdown is a human projection of this law, not the ultimate authority model.

## Claims discipline

This document distinguishes doctrine from observed capability. A named repository, package, or architectural path is not automatically `ALIVE` because it is described here.

Use the standing vocabulary:

- `ALIVE`: the claimed consequence was observed at an evidence coordinate.
- `PARTIAL_ALIVE`: bounded portions were observed; crown claim remains open.
- `BLOCKED`: an admitted dependency prevents the claimed execution.
- `BUILD_BROKEN`: the relevant verifier cannot currently be reached.
- `UNKNOWN`: evidence is absent, stale, or contradictory.
- `UNSUPPORTED`: outside the admitted boundary.

No prose outranks executable evidence.
